Why this demo exists - non-expert primer

🚨The customer problem

A Tier-1 supplier flags a defect on Tuesday morning. By end of day the after-sales lead at a major car manufacturer needs concrete answers: how many VINs are affected, which owners we must write to, which service centres are about to be overrun, and whether we can finish the work before the regulator's window expires.

Today this conversation spans six different systems: a parts catalogue, an as-built BOM database, a dealer-network capacity sheet, a parts logistics spreadsheet, an owner-notification ledger, and a senior manager's spreadsheet of "always pull these VINs first" rules.

5 active campaigns · 121 open recalls · 19 already past their SLA

🧩Why it's hard

The connections that matter cut across systems: supplier → part → bill-of-materials cohort → VIN → owner → service centre → region. Each step is a different team and a different join key. The "always prioritise VINs with a prior collision" rule lives in one person's head.

Doing this in SQL alone means manually re-deriving the cascade every time and re-hardcoding the priority rule into every report. Doing it with bespoke scripts means three or four hand-stitched data products that drift apart within a quarter.

Touch six systems, get the answer wrong 5-10% of the time, ship in 3 days

⚡How RelationalAI helps

One ontology over the same Snowflake data captures the relationships, the rules, and the policies in one place. Five different reasoners then share that ontology:

Rules audit the open recalls, a Graph reasoner walks the supplier→VIN cascade, a Heuristic ranks urgency, a Prescriptive MIP schedules jobs to centres, and a Persistent-rule capability lets the operator write the priority policy into the ontology so every downstream reasoner respects it without redeployment.

Same model, five reasoners, sub-minute answers, the policy survives

🏗️What the alternative looks like

Without RAI you'd assemble: a data engineer to wire the six joins, a data scientist to build the urgency model, an OR analyst to formulate the LP, and a senior product manager to keep the priority rules in a runbook. Three weeks of work, four maintenance owners, and the policies don't propagate when the data changes.

The talk track shows the same question landed in the agent that touches one model, in natural language, in under 90 seconds per question.

3 weeks + 4 owners → one ontology, one schema, an agent that answers in natural language

What you'll see - one ontology, five reasoners

The demo runs against {{DATABASE}} on the sales-engineering Snowflake account. 325 vehicles, 762 service events, 254 recall assignments across 5 active campaigns. A single PyRel ontology backs every act below; the Cortex agent {{AGENT_NAME}} answers all the same questions in natural language.

The fleet and service history come from two real BMW CSVs (BMW_VEHICLES_V1.csv, BMW_VEHICLES_SERVICES.csv - real WMIs, model codes, plants, mileages, accident records); the recall / supplier / BOM / service-centre / parts-stock layer is synthesised deterministically (seed=42) by data/build_cars_demo_data.py. The result is 14 tables across six data domains - product (vehicle, parts, BOM, plant), ownership (owner, region), risk (5 recall campaigns, 254 per-VIN assignments, 11 Tier-1 suppliers), service (15 service centres with HV/IBS/body-shop certifications, weekly capacity, per-week parts stock) - all wired together via the supplier -> part -> BOM-node -> VIN -> owner -> centre chain that the demo's reasoners traverse. Full schema in DATA_DICTIONARY.md.

If things break - demo-day triage

  • Engine not READY. .venv/bin/rai reasoners list to confirm. The gate auto-resumes them, but it can take 3-5 minutes cold.
  • Stale notebook in Snowsight. bash data/upload_snowsight_notebook.sh re-uploads.
  • Agent answering with stale schema. .venv/bin/python -m agent.deploy update refreshes sprocs without re-registering.
  • Solver returning INFEASIBLE. Not a runtime problem - the formulation drifted. Check data/out/cars_demo_validation.sql first; if data changed under you, regenerate. Otherwise the formulation needs /rai-prescriptive-problem-formulation.
  • Snowflake credentials. snow connection test -c rai. Profile lives in ~/.snowflake/connections.toml.
  • Cortex agent dies mid-demo. Fall back to .venv/bin/python -m agent.deploy chat "<question>" from the terminal. Slower (~90s per answer) but functional.
